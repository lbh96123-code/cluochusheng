# AD 选技助手 · 推荐算法与 09-24 实验

插件 v1.39.1 的推荐算法（GPU 版推演）+ 2026-09-24 围绕"推荐为什么奇怪"做的全部实验代码和结果。
训练数据、打分模型的训练见仓库根目录的起步包（`起步说明.md`）。

## 先定义几个词

| 词 | 意思 |
|---|---|
| 打分模型（考官） | 用真人对局训练的胜率模型：给十个人选满后的阵容打一个左队胜率（logit）。`plugin/engine/public/ad_model.js` + `ad_score.js` |
| 网络（直觉） | 自博弈 PPO 练出来的出手概率网络 `netB300.onnx`：看一眼局面，给每件能拿的东西一个概率。输入含"一步加分"（这件对当前选人涨多少分，已含与自己已有技能的配合） |
| 推演 | 假设我拿了某件，剩下的选人让所有人按网络概率抽样选到满编，交给考官打分；重复很多遍取平均 = 这件的胜率 |
| 一步加分 | 只看"现在拿这件立刻涨多少"，不管后面 |
| 标准答案 | 同一套推演算足（全部候选 × 64 局 → 前 8 名再补 512 局），= 模型眼里、噪声很小的最优。**不是实战真值** |

## 插件现在的算法（GPU 版，`plugin/combo_local.js`）

1. **后台筛选**（别人选的时候）：从当前真实局面，把我下一手的全部候选各推演 16 局 → 前 10 名各 32 局。
2. **决赛**（轮到我时）：筛选表前 5 名在准确局面各补到 32 局，先显示。
3. **更新**：准确局面全部候选重算一次（全部到 8 局 → 前 6 到 40 → 前 3 到 72），替换显示。
4. **推荐理由**（v1.39.1）：首推 ≠ 网络首选时，假设我改拿网络首选，推到我下一次轮到（128 局），看首推那件被谁拿走（`fate()`）。
5. 同一局面只过一次网络（去重）；显卡上一次 128 局约 4ms（4090，半精度）。

### v1.38 的种子 bug（v1.39 修复）
每局推演的随机数流 = `mix32(seed × 2654435761 + 局号)`，浮点乘法。插件的种子是英雄池哈希（1~5 亿），
乘出来 ~10¹⁷ > 2⁵³，`+ 局号` 被舍入掉 → 一批推演几乎共用一串随机数（160 局平均只有 5.8 串），
每个候选名义 32 局实际只推了一两种剧本，名次靠抽签（冷门技能排第一）。改成 `Math.imul` 后再加局号。
回归 `plugin/test/simrng_seed.js`（旧版必失败）。**教训：涉及种子的测试必须用真实量级的大种子。**

## 09-24 实验（代码在 `experiments/`，结果在 `results/`）

公共部分：`arena.js`（配对单座位对战场：77 个真实池子，1 个座位用被测方法，其余 9 人按网络抽样，
随机数只由盘号+手数决定，各方法轮流打同一盘）、`exp_local.js`（实验版推演库：温度、通用强制落子
`rolloutsG`、多起点推演、共享沙盘 `rolloutsShared`）。胜率都是考官（打分模型）口径。

| 实验 | 结论 |
|---|---|
| 对战 400 盘（`results/r1`） | A（v1.39 GPU 版）55.1% vs 纯网络直觉 50.1%（+5.0，t=11.5）；B 推演温度 1.5、C 两层展开均打平；C' 按最坏情况 −0.9（t=−2.5） |
| 吻合度 200 个决策点（`ref.js`，`results/r3`） | 与标准答案一致：A 84%、纯网络 56%；A 比最优差 >3 个点 0 次，纯网络 13.5%。安全阀不需要 |
| F 小 MCTS（`refF.js` `r4/r6`，对战 `r7`） | 虚拟损失"当作输一局"在胜率差只有 0.01~0.05 时会退化成照抄网络；改成"按当前胜率走一次"后仍不如 A，对战 −0.4（打平略输），每手 15 秒 → 放弃 |
| 实战 41 个决策点（`realpts.js`，`results/rp`） | 网络首选 = 最优 66%；网络吃亏的典型：断人（不拿下一手对面必拿）、"该谁拿"（队友拿不如我拿） |
| 趣味测试 949 个决策点（`playerpts.js`） | 各玩家实际选择 vs 标准答案：吻合率 35%~66%，平均少 0.6~2.7 个点；网络直觉 54% / 1.08 |
| 叠油局、复制之墙局（`napalm*.js` `cond.js` `optseq.js` `why.js` `order.js`） | 见下 |

### 目前唯一的大漏洞：强组合争夺时的"顺序赌博"
推演里**只有当前这一手在认真算，其他人都凭网络直觉**。网络低估某件东西（真人会早抓）时，推演会以为它会一直留给我，于是推荐"先拿弱配件，强的那件后面回来"：

- 蝙蝠局：推演认为先拿烈火罩（单件 −0.09），叠油 71% 会回到手里；而同一条两边最优路线里，下一手的对手认真算的第一名正是叠油。
- 09-24 15:14 那局：首推暗影波（单件 −0.01，windrun 胜率 49.9% 中游），价值全靠之后凑复制之墙（配合 +0.22）。推演以为复制之墙 95% 会留下，而真人平均第 21 手就抓复制之墙（前 27%）。算足后暗影波只排第 3（55.6 vs 巨牙海民 56.4），插件显示的"高 2.7 点"是 72 局的噪声。

`shared.js`（共享沙盘：所有推演局共用一张"局面 → 这件对落子方的平均结果"表，多轮推演中每个人按表调整）能让"先烈火罩"这种选择消失（烈火罩从第 1~3 掉到第 4~15），但每手 40 秒、结果波动大，不适合直接进插件。

下一步思路（未做）：只在强组合局面里，对"组合件 + 每人前几名的替代选择"做小范围倒推搜索，叶子用推演打分；把"对面会不会断"算清楚，再用进推演里的对手。
