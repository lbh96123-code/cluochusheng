# AD 选技 AI(RL)· 交接文档

> 给下一个会话:目标是**在现有胜负评分模型之上,训练/搜索出一个自动选技的 AI**。
> 本文档说清楚:评分模型是什么、它靠不靠得住、选技规则、手里有什么数据、建议怎么走、坑在哪。
> 2026-09-04 · 项目根目录 `game/ad-draft/` · 线上 http://43.130.62.185/ad/

---

## 0. 一句话

我们有一个"给定 10 个座位的完整阵容 → 左方胜率"的模型(AUC 0.763,校准好,浏览器里毫秒级算完)。
要做的是一个**选技策略**:在蛇形选技的每一手,从池子里挑一件东西放进自己的座位,使最终阵容按这个模型算出来的胜率最大。
这是一个 10 座位、50 手、池子 60 件的**完全信息回合制博弈**,评估函数现成且便宜。

## 1. 评分模型现状(reward 的来源)

### 1.1 是什么

| 项 | 值 |
|---|---|
| 线上模型 | `research/model_plan15_clr0.25.npz` → 导出为 `public/ad_model.js`(443 KB,随页面下发) |
| 训练数据 | 466,091 局 7.41d 补丁真实 AD 对局(windrun 抓取) |
| 输入 | 10 个座位 × 5 件东西的编号(前 5 座左方,后 5 座右方)。**只看编号**,不看顺序、不看玩家、不看赛后 |
| 输出 | 左方获胜 logit / 概率,附每座位分解 |
| 指标(测试集 69,914 局) | logloss 0.57733 · AUC 0.7627 · 方向判对 69.52% · 瞎猜 0.693 |
| 校准 | 十分位最大偏差 0.03,结算页可直接显示概率 |
| 640 件东西 | 127 个英雄本体 + 513 个技能,共用一张表 |

### 1.2 公式(三个模块相加)

```
座位分(s)  = Σ w_i  +  Σ_{i<j} 配合(i,j)             配合(i,j) = Σ_{k≤48} e_ik e_jk − Σ_{k>48} e_ik e_jk   ("切半",可为负)
队伍构成   = f(我方打钱分总和)  8 段分段线性          (5 个打钱位内耗)
跨队克制   = Σ_{i∈我方} ⟨a_i, u_敌⟩ − Σ_{j∈敌方} ⟨a_j, u_我⟩   u = 阵容在 15 条轴上的坐标
logit      = Σ_左 座位分 − Σ_右 座位分 + 构成(左) − 构成(右) + 克制
P(左赢)    = sigmoid(logit)          (天辉先手截距在模拟器里被扔掉,左右完全对称)
```

- 每件东西:`w`(单件强度,标量)+ `e`(96 维,决定和谁配)+ `a`(15 个克制系数)
- **反对称由结构保证**:左右对调 logit 变号(实测误差 1e-16)
- 三个模块贡献:切半配合 −0.0064 logloss(最大),构成 + 克制合计约 −0.002

### 1.3 接口

**JS(前端,推荐直接复用)** `public/ad_score.js`:
```js
evaluate(seats)                 // seats: 10×5 的 key 数组("hero:<id>" + 技能 key)→ {logit, prob, seats[10]{main,syn,cross,ctr,total}, team[2]}
rank(seats, seatIdx, candidates)// 给某座位试填每个候选,按 logit 增量排序 → [{key, delta}]   ← 贪心策略已经有了
explain(items)                  // 一个座位 5 件的单件 + 10 对配合逐条拆解
```
座位可以不满(选技中途也能评估)。整局评估实测 **0.043 ms**(node 18),`rank` 一手 40~60 个候选 ≈ 2~3 ms;贪心整局 21 局/s。

**Python** 前向:`research/ctr_axes_bench.py` 第 37–53 行是完整的 z0 + 克制前向(逐块,内存安全);
`research/counter_lib.py` 里有解析 `ad_model.js` 权重的代码。

### 1.4 它靠不靠得住 —— 用它当 reward 之前必须知道的

1. **排序可以信,数值不能当真。** 640 件东西两两组合 13 万对,中位共现只有 151 次;没见过的组合靠低秩"借力"给分。一个 +0.24 的配合分背后可能只有 157 局。**RL 会精准找到这些被高估的稀有组合**(见 §5 风险)。
2. **本事只有 19.5%。** draft 解释胜负方差的 19.5%(Murphy 分解),其余是操作/运气。同样的阵容换一局打,补刀 47% 是波动、KDA 92% 是波动。模型说 70% 就是 70%,不会更准。
3. **加法结构。** 座位内是"单件 + 两两配合",本体只能加减常数、不能当乘数。查过高射火炮×近战本体的案例:加法模型通过"本体和每个技能各扣一笔"实现了近似门控,残差没有系统性偏差(t=1.5),**目前不需要特殊化本体**。
4. **同类扎堆会被扣分。** 切半之后模型能说"两个范围治疗放一个座位是浪费"(对称 FM 做不到)。这对选技 AI 是好事:它不会无脑堆同类。
5. **克制项弱且粗。** 跨队克制总贡献 −0.002,且对轴是线性的;实测里有阈值效应(死亡旋风对面 ≥3 个力量英雄才跳 +4pp),模型只吃到 15%。**AI 不要指望模型能算细致的克制**;它主要靠座位内配合和单件强度。
6. **没有队伍层的角色概念**(除了打钱位内耗那一条)。"五个都是物理输出"模型看不见。
7. **训练数据是人类选的。** 模型在人类会选的阵容分布上准;AI 若选出人类从不选的阵容,模型对它的评分是外推,不可信。

### 1.5 正在做 / 刚做完(会影响 reward 版本)

- **克制轴替换**(2026-09-04 已验证):15 条手工轴 → 纯 e 主成分 16 条 + 本体/技能分开求和(`PC16+B`),与线上统计上无差别(t −0.09),零手工、零赛后统计。上线与否待定。**对 RL 无实质影响**,logloss 不变。
- **克制轴折点**(跑中):对属性计数轴加 max(数量−2,0),测阈值效应。预期影响很小。
- 结论:**reward 可以直接用线上版**,后续小改不会改变 AI 的学习目标。若想冻结版本,记住 `model_plan15_clr0.25` 这个名字。

### 1.6 文档

`doc/README.md` 索引三份:`半正定这道锁`(最新,结构发现 + 三模块 + 克制局限)、`ad_model`(算法与验证口径)、`ad_stats`(分段与原版强度)。`research/ctr_bench/RESULTS.md` 是克制轴对照实验。

## 2. 选技规则(模拟器 `server/draft.js`,以代码为准)

```
· 开 12 个英雄 → 池子 = 12 本体 + 36 普通技能 + 12 大招 = 60 件
  (大招被 AD 禁用或普通技能不足的英雄,随机从别的英雄补)
· 5v5,10 座位;两名玩家各代理 5 个座位(一人管一边)
· 每座位凑齐 1 本体 + 3 普通 + 1 大招 = 5 手;全场 50 手
· 每一手可选本体或技能,只要该座位对应槽还空着
· 座位级蛇形,一人一手交替:
    正向 左1 右1 左2 右2 左3 右3 左4 右4 左5 右5
    反向 右5 左5 … 左1
  五轮 正-反-正-反-正。轮次交界处同一座位连选两手(蛇形固有)
```

**和真实 Dota AD 的区别**(重要,决定 BC 数据能不能直接用):
- 真实 AD:本体随机分配、不可选;每人选 4 个技能(3 普通 + 1 大招);池子 = 12 英雄的 48 个技能
- 模拟器:**本体也是选的**,每人 5 手
- 所以真实对局的 pick 顺序数据只能给"技能选择"做行为克隆,"本体选择"没有人类数据

## 4. 建议路线:先搜索,后 RL

评估函数便宜(1 ms)、状态完全可见、分支有限(≤60)、深度 50,这是**搜索的主场**。RL 不是第一选择。

### 第 0 级:贪心(已有)
`rank()` 就是贪心:每手选 logit 增量最大的。先把它当 baseline 测出来。

### 第 1 级:带前瞻的贪心 / 束搜索
- 考虑"这件东西如果我不拿,对面下一手会拿走"(蛇形下对手的下两手是可预测的)
- 束搜索宽度 5~10,深度 2~4 手,每手用 `evaluate` 打分
- 一手几百次评估,浏览器里 <1 s,**可以直接放进线上当 AI 对手**

### 第 2 级:MCTS,以模型为终局评估
- 完全信息、双方交替、终局 = `evaluate` 的 logit(不用 rollout 到底,残局用贪心补满再评估)
- 对手建模:对手也按同一策略(自博弈)或按人类 BC 策略
- 几千次模拟/手,服务端 node 里跑得动

### 第 3 级:RL(只在这些情况下才值得)
- 需要**毫秒级响应**且搜索太慢(先测,大概率不会)
- 需要**对手建模**:线上对手是人,人不按最优选;策略网络能吸收人类分布
- 想做 AlphaZero 式:MCTS 产生目标,策略网络蒸馏,再指导 MCTS —— 这是最靠谱的 RL 用法

**RL 建模建议**(如果做):
```
状态   自己 5 座位已选 + 对方 5 座位已选 + 剩余池子(60 维 one-hot)+ 当前是哪一手/哪个座位
动作   池子里对该座位合法的候选(槽位约束)
奖励   终局 sigmoid(logit) 或 logit 本身(logit 更线性,方差更小);中间 shaping 用 Δlogit 要谨慎(会诱导短视)
多座位 一名玩家管 5 座,策略共享,座位序号作为输入
自博弈 双方共用一个策略,交替更新;混入 BC 人类策略当对手,防止自博弈漂移到怪阵容
初始化 用真实 pick 顺序做行为克隆(只对技能;本体没人类数据)
```

## 5. 最大风险:奖励黑客(reward hacking)

评分模型是从人类阵容学的**近似**。优化器会找到它的错误并放大:
- 稀有组合被高估(157 局的 +0.24)
- 人类从不组的阵容,模型外推
- 克制项粗,AI 可能过度堆"对模型而言"克制的东西

**缓解措施(建议至少做前三条)**:
1. **支持度惩罚**:每对组合的训练集共现次数是现成的(`research/` 里有 `counter_matrix.npz`、共现统计);共现 <300 的配合分打折或置信区间下界
2. **集成 / 不确定性**:文档里提到 10 模型融合(0.5814,未上线);用多个模型的**最小值或分位数**当 reward,而不是均值
3. **离线真实验证**:AI 策略在真实池子上重放,凡是 AI 的选择和人类一致的局,看真实胜率;AI 独有的选择无法验证 —— 统计它们占比,越高越危险
4. **人评**:在模拟器里让人打 AI 的阵容,主观判断"这阵容像不像人会组的"
5. **约束动作空间**:只允许在人类 pick 分布里出现过 ≥N 次的(座位内)组合;或对 KL(π‖π_BC) 加惩罚
6. 定期用**未来验收集**(`holdout.jsonl`)重新检查评分模型自身没漂

## 6. 评估协议

- 固定 200 个随机池子(`buildPool` 带 seed),每个池子让策略 A 管左、B 管右,再交换边,取平均 —— 消除先后手
- 指标:模型胜率(主)、支持度加权胜率(防黑客)、平均座位分、"人类相似度"(与 BC 策略的一致率)
- 对照:随机 / 贪心 / 束搜索 / MCTS / RL,全都过同一套
- 至少一次让评分模型**换版本**(旧版 `multitask_K96_lam10.0_win` 339 KB 还在 `doc/ad_model` 描述的口径)重评,看结论稳不稳 —— 策略对 reward 版本敏感 = 在黑客

## 7. 机器与工程约束(硬)

- **AWS 本机(8 GB)跑着实盘交易进程**:不能做重训练;单实验 ≤2 GB、`nice -n 15`、不并行。用它做分析/评估
- **腾讯云 43.130.62.185(2 核 / 1.96 GB)**:跑着游戏服务(`aegis`、`zyb`、`aegis-train`)。能训小模型,但 RSS >1.2 GB 就会挤到页缓存;`/root/adres` 有数据和脚本。连接方式见 `calet_trading/tmp_setup_myserver_pem.sh`(sshpass + pem)
- 没有 GPU、没有 torch。可用:numpy / scipy / node。之前的 RL 都是**手写 numpy 或 JS 的 MLP**
- 线上 AI 若放前端,只能用 JS;放服务端可以 node

## 9. 建议的第一周

1. 用 `rank()` 贪心 + 束搜索 + 随机,跑 §6 的评估协议,拿到三条基线 —— **半天**
2. 从 `matches_big.jsonl` 抽 pick 顺序,做技能选择的行为克隆(线性/小 MLP),同时统计"人类选择 vs 贪心选择"一致率 —— 知道人类离模型最优有多远 —— **一天**
3. MCTS(node),自博弈 + BC 对手,对贪心/束搜索 —— **两天**
4. 只有 MCTS 明显优于束搜索、且太慢时,再考虑策略网络蒸馏(RL)
5. 全程盯 §5:每个新策略都报"独有选择占比"和"支持度加权胜率"
